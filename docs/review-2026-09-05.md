# Repository review — 2026-09-05

Scope: Compose, both Dockerfiles, the Hailo detector patch, shell helpers, example configuration, and documentation. Recommendations below are not applied by the RC1 version update.

## Prioritized actions

1. **Restrict published service ports.** `compose.yaml` publishes ports 5000 and 1984 on all host interfaces. Bind internal API access to localhost or a trusted interface and expose the authenticated Frigate listener (8971) through the intended access path. Verify Home Assistant and go2rtc integrations before changing bindings.
2. **Make release checks repeatable.** Add a release script or CI job that builds ARM64, imports both detector plugins, validates the example config with Frigate, checks HailoRT, and verifies remote tag digests after publishing. Run real-camera inference separately on the Pi before promoting a release for production.
3. **Reduce image contents.** Both Dockerfiles copy the entire packages directory into a persistent layer. This includes unused wheels and PCIe driver packages on this host; deleting them in a later layer does not remove those bytes. Copy only the selected DEB/wheel or use BuildKit bind mounts for installation.
4. **Pin build inputs.** `VLM_REF=main`, `debian:trixie-slim`, and unpinned pip dependencies can change between builds. Pin upstream revisions and base-image digests, and record package checksums. Add image version/revision labels and point the source label at this repository while retaining upstream attribution.
5. **Keep installation failures visible.** The Frigate Dockerfile suppresses apt/dpkg stderr and tolerates pip uninstall failure. Preserve diagnostics and assert the installed HailoRT version after installation so dependency repair cannot silently remove a required runtime package.
6. **Tighten runtime defaults.** Review whether `PERFMON` is needed on this ARM64 deployment, make detector debug logging opt-in, and size shared memory/cache for camera count. Use a versioned image tag when automatic release-candidate updates are undesirable.
7. **Separate current and historical validation.** Document exactly which release passed image/config checks versus camera inference and simultaneous Frigate/VLM hardware use. Add a backup/restore procedure that captures SQLite consistently before database migration.
